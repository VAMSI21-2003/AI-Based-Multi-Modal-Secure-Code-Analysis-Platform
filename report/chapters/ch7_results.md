### 7.2.2 Training vs. Testing Performance / Bias-Variance Reading

`models/training_metadata.json` records only test-set metrics for the final models (no separate
training-set score is persisted for the production run), so a direct train/test gap cannot be quoted
from that artifact. What can be said, and is a more informative statement in this case: the modest
absolute F1 (0.5391) combined with the modality-ablation finding that four different CodeBERT-inclusive
feature subsets all land within 1.2 F1 points of each other on the same test set (Chapter 3.4.3)
indicates the model is closer to a signal-ceiling for this feature representation on this dataset than
to an overfitting problem that more regularization or more data would straightforwardly fix — recall in
particular (0.5219) shows the model still misses close to half of the true vulnerable functions in the
test set, which is a genuine capability limit, not a symptom of overfitting the training data.

### 7.2.3 Model Comparisons

Beyond the two production models, the modality-ablation experiment (Chapter 3.4.3) trained the same
XGBoost configuration on each individual and paired feature subset, giving a broader comparison than
Random-Forest-vs-XGBoost alone:

**Table 7.4: Modality-ablation results, restated from Chapter 3.4.3 for direct comparison**

| Subset | F1 | AUC-ROC |
|---|---|---|
| AST only | 0.4939 | 0.5757 |
| Metrics only | 0.4797 | 0.5883 |
| AST + Metrics | 0.5018 | 0.6076 |
| CodeBERT only | 0.5418 | 0.6309 |
| CodeBERT + Metrics | 0.5326 | 0.6328 |
| CodeBERT + AST | 0.5444 | 0.6327 |
| **Full fusion (production)** | **0.5391** | **0.6346** |

As discussed in Chapter 3.4.3, this shows a clear win for including CodeBERT over structural-only
features, but not a clean win for full fusion over CodeBERT alone at the F1 level — full fusion's
advantage is its AUC-ROC, the highest of any subset.

## 7.3 Comparison with Existing Systems — and a Disclosed Correction

Chapter 2.4 compares this project against prior published systems on the same Devign lineage: the
Devign GNN baseline and fine-tuned CodeBERT on the CodeXGLUE Devign split (≈62.1% accuracy, Lu et al.,
2021). This project's XGBoost result (Accuracy 0.5932, F1 0.5391) is below the CodeXGLUE
fine-tuned-CodeBERT accuracy figure — an honest result to report rather than round away.

This project's own internal documentation (`paper/research_paper.md`) discloses that this was not
always the reported outcome, and the discrepancy is worth explaining rather than omitting. An earlier
implementation attempt of the feature-fusion step (`src/fusion/fuse_features.py`) joined the AST,
metrics, and CodeBERT feature tables using each table's own row position rather than a shared function
identifier. A later forensic audit (`docs/ML_FORENSIC_AUDIT_PHASE4.md`) discovered that, because the
AST- and metrics-extraction scripts applied a different minimum function-length filter than the
CodeBERT-extraction script, the three tables' row positions had silently drifted apart during
preprocessing — measured at **99.35% of fused rows** pairing one function's label and structural
features with a different function's CodeBERT embedding. Every metric computed on models trained from
that fused table was therefore invalid, even though the pipeline ran without any error. The defect was
corrected by threading the `original_id` identifier already introduced during preprocessing
(Chapter 3.3.3) through every extraction script and re-joining on that stable key
(`src/fusion/fusion_core.py`), and the production models were retrained on the corrected, correctly
paired feature table on 2026-07-21 (`models/ml_baseline_status.json` records this as the fix date, with
`fusion_alignment_status: "fixed"`). A dedicated regression-test file
(`tests/test_fusion_alignment.py`, 12 tests, Chapter 6.1.1) now specifically guards against this class
of defect recurring — for example, verifying that shuffling each table's row order before fusion
produces an identical result, and that a deliberately mismatched label across tables raises an error
rather than silently fusing.

Before this fix, the project's own earlier report drafts (`paper/project_report_part1.md`,
`project_report_part2.md`, `paper/results_section.md`) reported a substantially higher, but invalid,
performance figure (Accuracy 84.00%, F1 0.8242, AUC-ROC 0.998) computed on the misaligned data. **This
report uses only the corrected, verified figures throughout** (Accuracy 0.5932, F1 0.5391, AUC-ROC
0.6346) and states this correction explicitly, on the view that disclosing a found-and-fixed data
integrity defect is a legitimate and important methodological result in its own right, not a weakness
to conceal. It is also the reason this project's own reported result now falls slightly below, rather
than above, the Devign GNN and CodeXGLUE CodeBERT baselines it is compared against in Chapter 2.4 — a
direct, honest consequence of correcting the defect rather than reporting the number the earlier,
uncorrected pipeline produced.
